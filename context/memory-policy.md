# 长期记忆的维护

默认由用户手动维护；AI 只有获得**针对具体内容和保存范围的明确同意**后才可更新长期记忆。已有明确授权可直接执行，无需重复申请。访问或推送权限、一次交接请求、一般任务完成、用户没有反对，都不等于长期保存同意。

| 类型 | 唯一归属 | 维护规则 |
| --- | --- | --- |
| 稳定偏好 | `context/preferences.json` | 只保存用户明确确认且适合长期复用的偏好；不从单次行为推断 |
| 项目规范和决策 | `projects/<代号>/PROJECT.md` | 在该项目授权维护范围内更新；保留理由和来源 |
| 项目动态 | `projects/<代号>/STATUS.md` | 记录检查日期、证据、未知项；不视为全局偏好 |
| 会话交接 | `handoffs/<代号>/<日期>-<主题>.md` | 用户要求时生成；记录当前快照，不自动提升为长期记忆 |

需要提议偏好变更时，使用 [变更模板](../templates/preference-change.md)，说明新增、修改或删除什么、原因、适用范围和来源。授权不明时只在聊天或 `.local/` 提供提案；不要创建自动生效的候选记忆。

偏好条目字段：`id`、`statement`、`scope`、`confirmed_on`（ISO 日期）、`source`（不敏感的确认摘要）。`source` 记录确认方式即可，不贴私人对话、不发明证据。无效或撤回的偏好从源文件删除或修改；提交记录保留变更经过。同步后的 AI 需要重新读取该版本，旧上传包不会自动失效。

本规则只管理本仓库内容。各 AI 产品的内置记忆、历史记录和数据保留由各自设置独立控制；不能声称此规则已经关闭或同步平台记忆。
